# Repository Deep Research Audit

Date: 2026-05-31

## Scope

This note documents a repo-level audit of `OrganoidSensor`, including:

- repository structure and git state,
- paper generation tooling,
- LaTeX and figure reproducibility,
- manuscript/source consistency,
- scientific literature spot checks,
- recommended remediation steps.

No files were edited during the original audit. This document records the findings for future reference.

## Repository Snapshot

The repository currently functions as a generated paper and research artifact repo, not as an application scaffold.

Current committed content includes:

- `AGENTS.md`: general repository and agent workflow guidelines.
- `references/`: research notes and source material.
- `paper/nature_submission/main.tex`: generated Nature-style LaTeX manuscript.
- `paper/nature_submission/main.pdf`: compiled PDF artifact.
- `paper/nature_submission/figures/`: generated image figures, captions, prompts, and API logs.
- `tools/paper_writer/`: shell and Python tooling for manuscript generation, figure generation, and LaTeX compilation.

Missing expected application scaffolding:

- no `src/`,
- no `tests/`,
- no root `README.md`,
- no `Makefile`,
- no dependency file or lockfile,
- no analysis notebooks or reproducible data pipeline.

Git state observed during audit:

- branch: `master`,
- latest commit: `feat: add paper writer toolchain and generated Nature-style manuscript`,
- no remote configured,
- worktree clean after removing local Python bytecode generated by syntax checking.

## Main Finding

The repo is best understood as a concept-paper generation repository. The manuscript reads like an empirical research paper, but the repository does not contain the data, protocol outputs, analysis code, or tests needed to support the empirical claims.

Examples of unsupported manuscript claims:

- 512-channel layer-resolved recordings,
- 45-day functional stability,
- 12 dB signal-to-noise improvement,
- 89 percent trajectory reconstruction accuracy,
- independent-organoid validation,
- released event detection, spike sorting, and neuromorphic decoding code.

These claims may be suitable as proposal targets or design requirements, but they should not be presented as completed experimental results unless primary evidence is added.

## Toolchain Findings

### Paper Writer Scripts

The paper writer stack is cohesive but highly automated:

- `prompt_tool_1_write_paper.sh` asks `codex exec` to write `main.tex` from local references.
- `prompt_tool_2_optimize_and_generate_figures.sh` asks `codex exec` to optimize figure prompts and then calls `grsai_generate_figures.py`.
- `prompt_tool_3_compile_paper.sh` compiles LaTeX and uses `codex exec` to auto-fix compile failures.
- `run_paper_toolchain.sh` runs all three tools and then commits and may push generated changes.

### Portability Issues

Several scripts default to a macOS-specific path:

```bash
/Users/lachlanchen/Documents/iProjects/OrganoidSensor
```

The audited workspace path was:

```bash
/home/lachlan/ProjectsLFS/OrganoidSensor
```

This makes the default script behavior non-portable unless the repo root is always passed explicitly.

### Auto-Commit Risk

`run_paper_toolchain.sh` stages `paper`, `tools`, and `references`, commits generated changes, and pushes if an `origin` remote exists. This is risky because:

- generated AI outputs can change substantially between runs,
- external API outputs are not deterministic,
- prompt response files and logs may be large or sensitive,
- review should happen before commit and push.

Recommended change: make commit/push opt-in, for example behind `--commit` and `--push` flags.

### Secret Handling

`grsai_generate_figures.py` reads the API token from `GRSAI` and sends it as a Bearer token. No secret was found committed in the repo. However, generated API logs are committed under `paper/nature_submission/figures/logs/`; they currently contain output URLs and task responses. These logs should be reviewed before public release because external service logs can expose identifiers, URLs, or metadata.

The optimized prompt rules require no rendered text in images, and the generation script prepends "No watermark. No logo." Despite that:

- `fig05_quality_control_monitoring.png` contains visible "GRS AI Nano Banana" branding and chart labels.
- `fig06_ethics_and_deployment_framework.png` contains rendered labels.

## Manuscript Findings

### Empirical Framing

The manuscript uses direct empirical language such as "We report", "We implemented", and "Across n=6 organoids". The repository does not contain:

- raw electrophysiology,
- processed event streams,
- spike sorting outputs,
- decoder training code,
- statistical notebooks,
- protocol records,
- microscopy data,
- metadata for organoid batches,
- ethics approval documents.

Recommended change: either add the missing evidence or rewrite as a review, blueprint, or proposal.

### Availability Statements

The Data Availability and Code Availability sections are not satisfied by this repo. In particular, the code availability section says custom code is released under an open-source license at a public repository to be provided upon acceptance, but this repository does not include that code.

Recommended change: replace these statements with accurate repo-specific language or add the promised code and data access instructions.

### Bibliography Accuracy

The bibliography needs source-by-source verification. Some cited concepts are real, but several entries appear inaccurate or fabricated in details such as authors, journal, year, volume, or pages.

Example:

- The manuscript cites "Shupe, T. & colleagues. Brain organoid reservoir computing for artificial intelligence. Nat. Electron. 6, 873-884 (2023)."
- The actual Nature Electronics article is Cai, H., Ao, Z., Tian, C. et al., "Brain organoid reservoir computing for artificial intelligence", Nature Electronics 6, 1032-1039 (2023), DOI `10.1038/s41928-023-01069-w`.

Recommended change: rebuild the bibliography from primary sources and add DOI links.

## Scientific Literature Spot Checks

The manuscript combines several plausible research directions, but the combined "complete bio-hybrid vision system" is not established by the repo.

### Supported Background Areas

Retinal organoid cone light responses:

- Saha et al. showed human stem-cell-derived retinal organoid cones can produce graded, repetitive, wavelength-specific light-evoked responses comparable in aspects to primate foveal cones.
- Source: https://pmc.ncbi.nlm.nih.gov/articles/PMC9093561/

CYST retinal organoid protocol:

- Neuroepithelial cyst-based human retinal organoid protocols can generate reproducible retinal organoids and relatively cone-rich cell composition across multiple hiPSC lines.
- Source: https://pmc.ncbi.nlm.nih.gov/articles/PMC10587494/

IGF1-PHLDA1 axis:

- Single-cell transcriptomic work supports a role for IGF1-PHLDA1 signaling in photoreceptor precursor specification.
- Source: https://pmc.ncbi.nlm.nih.gov/articles/PMC9645368/

Electrical field stimulation:

- A study of day-80 retinal organoids reported that a single 60-minute biphasic electrical field exposure modulated retinal cell development, increasing photoreceptor-related markers while downregulating some RPE and RGC-associated genes.
- Source: https://pmc.ncbi.nlm.nih.gov/articles/PMC11639233/

3D liquid-metal MEAs:

- Magnetically reshapable 3D liquid-metal MEAs have been reported for electrophysiological analysis of brain organoids.
- Source: https://www.nature.com/articles/s41467-024-55752-3

Organoids-on-chip:

- Retinal organoid micro-millifluidic bioreactors and broader organoid-on-chip systems have literature support for long-term maintenance and microenvironment control.
- Sources:
  - https://pmc.ncbi.nlm.nih.gov/articles/PMC8387452/
  - https://pmc.ncbi.nlm.nih.gov/articles/PMC11933005/

Biosensor-organoid interfaces:

- Recent reviews support the integration of organoids with microfluidics, MEAs, optical sensors, FETs, impedance, SPR, and mass spectrometry imaging for multimodal monitoring.
- Source: https://pmc.ncbi.nlm.nih.gov/articles/PMC12467644/

Ethics and organoid intelligence:

- Ethical concerns around organoid intelligence include moral status, consciousness/cognition, oversight, consent, chimeras, commercialization, and public engagement.
- Sources:
  - https://www.frontiersin.org/journals/artificial-intelligence/articles/10.3389/frai.2023.1307613/full
  - https://www.isscr.org/policy/guidelines-for-stem-cell-research-and-clinical-translation

### Unsupported or Needs Verification

The repository does not currently verify:

- an event-based retinal organoid camera implementation,
- 512-channel retinal organoid recordings,
- organoid-to-decoder trajectory reconstruction at 89 percent accuracy,
- a 12 dB SNR improvement versus frame sampling,
- 45-day operation of the specific integrated stack,
- optogenetic shunts in the same platform,
- vascularized retinal organoid integration into the described MEA/microfluidic system,
- the specific event-imaging citation in the manuscript.

## Recommended Remediation Plan

### 1. Clarify Repository Identity

Choose one of two directions:

- Concept/review/proposal repo: rewrite `main.tex` to avoid empirical claims and present the work as a design blueprint.
- Experimental/software repo: add data, code, analysis, tests, and reproducible protocols that support the claims.

### 2. Add Root Documentation

Add a root `README.md` covering:

- repo purpose,
- current artifact status,
- prerequisites,
- exact reproduction commands,
- known limitations,
- where generated outputs live,
- how to avoid auto-commit/push behavior.

### 3. Make Tooling Portable

Change scripts so default root is resolved from the script location, for example:

```bash
ROOT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")/../.." && pwd)"
```

Keep explicit root arguments as an override.

### 4. Remove Default Auto-Publish

Change `run_paper_toolchain.sh` so commit and push are opt-in. Recommended behavior:

- generate artifacts,
- print `git status`,
- stop for review,
- commit only when `--commit` is passed,
- push only when `--push` is passed.

### 5. Add Reproducibility Metadata

Track:

- Codex model and prompt versions,
- GRS AI model name,
- generation date,
- figure prompt JSON hashes,
- TeX distribution/package requirements,
- expected output checksums where appropriate.

### 6. Fix Figures

Regenerate or manually replace figures that contain:

- logo or watermark,
- rendered text when the prompt forbids text,
- clipped labels,
- file extension/content mismatch,
- black bands or inconsistent styling.

### 7. Rebuild Bibliography

Create a verified bibliography table with:

- claim supported,
- citation key,
- full citation,
- DOI/URL,
- notes on whether the source supports background, method, or direct empirical result.

### 8. Align Availability Statements

If this remains a concept paper:

- state that no primary datasets were generated,
- state that code is limited to paper-generation tooling.

If this becomes an empirical paper:

- add data access instructions,
- add analysis code,
- add scripts to reproduce tables/figures,
- add tests for event detection and decoding code.

## Bottom Line

The repository is useful as a generated concept-manuscript workspace. It is not yet a reproducible scientific software or empirical paper repository. The highest-priority fixes are to correct the manuscript framing, verify citations, make tooling portable, disable default auto-push behavior, and replace non-compliant generated figures.
